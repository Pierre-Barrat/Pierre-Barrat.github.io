Dashboard de gestion de cluster Hyper-V

Une interface web pour voir en un coup d'œil l'état des machines virtuelles du cluster et les piloter à distance.

  • PowerShell
  • Runspace pool
  • PHP
  • IIS
  • Hyper-V
  • JSON
  • Tâche planifiée
  • bcrypt

Contexte

Le cluster Hyper-V est administré depuis un serveur Active Directory central. Pour connaître l'état des VM et choisir sur quel nœud en démarrer une, il fallait ouvrir le Gestionnaire Hyper-V dans le navigateur sur le réseau privé. Le but : une vue consolidée, accessible depuis un navigateur.

Fonctionnalités

  • Tableau des VM de tous les nœuds, avec en-tête fixe et défilement
  • État de chaque serveur calculé dynamiquement à partir des métriques
  • Recommandation du serveur le plus adapté pour démarrer une VM, via un score pondéré (CPU libre, RAM libre, vCPU)
  • Démarrage et arrêt d'une VM depuis l'interface
  • Accès protégé par une authentification à compte unique sur le réseau interne (mot de passe haché basiquement)

Architecture

Navigateur
    │  HTTPS
    ▼
Interface PHP (IIS)
    │  lit / écrit des fichiers JSON
    ▼
Dossier réseau partagé  ◄────────  Script PowerShell (tâche planifiée)
 (état des VM, file d'actions)         │  -ComputerName (accès distant)
                                       ▼
                              Nœuds du cluster Hyper-V
  • Collecte : Get-VmdashboardDataV2.ps1 s'exécute en tâche planifiée et interroge les nœuds en parallèle (runspace pool).
  • Communication : un dossier réseau partagé sert de couche d'échange — PowerShell écrit les données en JSON, PHP les lit.
  • Actions : un clic sur « démarrer » ou « arrêter » dépose une demande dans queue.json (champ action), traitée par le script PowerShell.

Difficultés rencontrées

  • Un nœud ralentissait toute la collecte. Ajout de logs de durée par VM et par appel pour repérer que le nœud hébergeant le plus de VM dominait le temps total.
  • Résultats parallèles traités dans le mauvais ordre. Remplacement de EndInvoke() par WaitHandle.WaitAny() pour récupérer chaque résultat dès qu'il est prêt.
  • Messages affichés en double. Cause : le passage de $Host au constructeur du runspace pool.
  • Tâche planifiée qui ne se répétait pas. Il manquait -RepetitionDuration ([TimeSpan]::MaxValue) dans le déclencheur.
  • Échec de démarrage de VM sur certains commutateurs virtuels. Ajout d'une fonction Repair-VmNetworkAdapterSwitch exécutée avant Start-VM.

Choix techniques

  • Première version avec PHP sur IIS avec appel PowerShell à la demande.
  • Authentification par un compte unique bcrypt, plus simple à déployer.
  • Jeu de 8 fichiers de référence (JSON) avec une nomenclature en français.

Livrables

  • Guide de déploiement de A à Z : configuration d'IIS, permissions des dossiers, prérequis WMI et pare-feu, HTTPS.
